### Version 0.7.0: Rename Across Files and Lower Memory Use
- **Breaking change:** renaming an IRI (F2) now also renames it in all other indexed files that reference it, including SPARQL queries and RDF/XML documents. Only the local name is replaced, so every prefix and syntax a file uses stays valid. The changes in other files are shown in the *Refactor Preview* before they are applied, and they are undone in one step. Set `mentor.editor.renameAcrossFiles` to `false` (*Editor → General* in the Mentor settings) to rename within the document only, as before. Prefixes, variables and blank nodes are still renamed within the document
- *Go to Definition* now opens the framework vocabularies shipped with Mentor (RDF, RDFa, RDFS, OWL, SHACL, SKOS, SPARQL and XSD) and the preset SHACL shapes in read-only documents, e.g. for `rdfs:label` or `owl:Class`; a definition in a workspace file takes precedence
- The XSD vocabulary now covers many more XSD 1.1 datatypes, such as `hexBinary`, `gYear`, `language`, `token` and `dateTimeStamp`, and the constraining facets, such as `xsd:pattern` and `xsd:minInclusive`, with labels, descriptions and links to the specification (contributed by [@otellomaria](https://github.com/otellomaria))
- *Go to Definition* while the workspace is indexed now waits for the index and returns the definition, instead of a reference in the current document ([#147](https://github.com/faubulous/mentor-vscode/issues/147))
- Much lower memory use for large workspaces: indexed files that are not open no longer keep their syntax tree and tokens, and the index of a document is stored compactly ([#112](https://github.com/faubulous/mentor-vscode/issues/112), [#124](https://github.com/faubulous/mentor-vscode/issues/124)). In a test workspace of 101 files with 400k triples, the memory retained after indexing dropped from 1.8 GB to about 0.5 GB
- The inferred triples of deleted and renamed files are now removed from the index, and *Reindex Workspace* clears the triple store at once instead of deleting it graph by graph ([#115](https://github.com/faubulous/mentor-vscode/issues/115))
- SPARQL query history no longer keeps the results of older queries in memory, in the persisted workspace state and in the messages to the results view ([#113](https://github.com/faubulous/mentor-vscode/issues/113)); the results view no longer re-runs a query when it is shown again, and filtering large result tables no longer rebuilds the table on every keystroke ([#114](https://github.com/faubulous/mentor-vscode/issues/114))
- Faster start-up: Mentor activates while VS Code starts in workspaces that contain RDF files, loads the SPARQL query engine on the first query and the framework vocabularies after activation, and computes the workspace-wide problems after indexing instead of during it ([#119](https://github.com/faubulous/mentor-vscode/issues/119), [#150](https://github.com/faubulous/mentor-vscode/issues/150))
- Faster loading and editing of large files: valid Turtle documents are read without building a syntax tree ([#127](https://github.com/faubulous/mentor-vscode/issues/127)), VS Code stays responsive while large files load ([#120](https://github.com/faubulous/mentor-vscode/issues/120)), an opened document answers *Go to Definition* before its triples are loaded ([#143](https://github.com/faubulous/mentor-vscode/issues/143), [#144](https://github.com/faubulous/mentor-vscode/issues/144)), and completions do much less work per keystroke ([#116](https://github.com/faubulous/mentor-vscode/issues/116))
- Edits of large documents apply only the triples that changed, instead of replacing all triples of the document, and skip the inference when no triple changed, e.g. after editing a comment ([#120](https://github.com/faubulous/mentor-vscode/issues/120)); *Reindex Workspace* loads the documents open in an editor once instead of twice
- Turtle documents are parsed about 40% faster, as the index of their resources is built with fewer allocations; indexing a workspace of 101 files with 400k triples takes 1.8 s instead of 2.2 s
- Switching between editors no longer re-runs SHACL validation, linting and definitions tree rebuilds for unchanged documents ([#117](https://github.com/faubulous/mentor-vscode/issues/117)), and the definitions tree creates its items with fewer queries, showing tooltips when an item is hovered ([#118](https://github.com/faubulous/mentor-vscode/issues/118))
- Sub-properties without their own range or domain now inherit those of their super-properties, so the definitions tree shows e.g. the boolean or number icon for them
- Fixed RDF/XML element names and prefixes with upper-case letters, such as `<ex:MyClass>` or `xmlns:dcTerms`, not being found by *Go to Definition* and *Find Usages* ([#130](https://github.com/faubulous/mentor-vscode/issues/130))
- Fixed commented-out elements in RDF/XML documents being treated as definitions
- Fixed properties with an `xsd:unsignedLong` or `xsd:unsignedByte` range not being shown as data properties with a number icon in the definitions tree
- Fixed the definitions tree staying empty for the document that is open when VS Code starts ([#156](https://github.com/faubulous/mentor-vscode/issues/156))
- Updated mentor-rdf to 2.4.0 and mentor-rdf-parsers to 2.2.1, and removed the direct dependency on N3.js ([#154](https://github.com/faubulous/mentor-vscode/issues/154))

### Version 0.6.6: Workspace and SKOS Fixes
- Files and folders that are moved, renamed or deleted outside of VS Code, e.g. in a terminal or by a `git checkout`, are now reflected by the workspace tree and the index ([#95](https://github.com/faubulous/mentor-vscode/issues/95)); the index drops the graphs and problems of deleted files, indexes moved-in files and re-indexes files that were changed on disk
- *Reindex Workspace* and *Refresh Tree* in the workspace tree now discover the workspace files again, so they recover from changes the file watcher did not report
- Fixed the workspace tree listing the files of a sibling folder whose name starts with the same characters, e.g. `old2/` below `old/`
- The definitions tree now shows SKOS concepts that are not in a concept scheme and cannot be reached from one ([#101](https://github.com/faubulous/mentor-vscode/issues/101)), and SKOS collections that are not in a concept scheme ([#96](https://github.com/faubulous/mentor-vscode/issues/96)); they are listed below their source of definition or *Unknown*, or in their own nodes when grouped by type
- Fixed SKOS collections with `skos:inScheme` being inferred to be concepts and listed below the concepts of their scheme ([#96](https://github.com/faubulous/mentor-vscode/issues/96))
- Fixed the definitions tree not showing a document after its language was changed, e.g. an unsaved file switched from *Plain Text* to *Turtle* ([#104](https://github.com/faubulous/mentor-vscode/issues/104))
- Prefixed names are now highlighted correctly when the prefix contains a hyphen in TriG and Datalog ([#97](https://github.com/faubulous/mentor-vscode/issues/97)), and when the name contains colons, escaped characters or non-ASCII characters in all languages ([#106](https://github.com/faubulous/mentor-vscode/issues/106), [#107](https://github.com/faubulous/mentor-vscode/issues/107), [#108](https://github.com/faubulous/mentor-vscode/issues/108)); a period that ends a statement is no longer highlighted as part of a name, and the colon of the `:-` operator in Datalog rules is no longer highlighted as a prefix
- Fixed prefix names that start with a keyword, such as `prefix:`, `base:` or `true:`, failing to parse ([mentor-rdf-parsers#5](https://github.com/faubulous/mentor-rdf-parsers/issues/5))
- Updated mentor-rdf to 2.1.8, mentor-rdf-parsers to 2.1.1 and mentor-rdf-serializers to 1.9.2
- Resolved the advisories of the build and test dependencies, including the packaging tool (@vscode/vsce 4)

### Version 0.6.5: Exporting Query Results
- Query results can be exported as a Markdown table or as SPARQL Query Results JSON, next to the existing CSV export
- The results toolbar sets whether an export opens in a new document or goes to the clipboard, and the choice can be defaulted in the settings
- Copying the output of a notebook cell now yields the results table ([#89](https://github.com/faubulous/mentor-vscode/issues/89)); the cell previously offered its results only as `application/sparql-results+json`, which the built-in *Copy Cell Output* command cannot read, so it silently copied nothing. The same affected CONSTRUCT and DESCRIBE cells
- A new *Query → General* settings section sets the export target, whether IRIs are written in full or prefixed, and the format a notebook cell offers to the copy command
- The definition tree now lists predicates that a data document only uses, whose definitions live in another document ([#90](https://github.com/faubulous/mentor-vscode/issues/90)); the reasoner infers a property from its use as a predicate
- The raw HTTP response of a query moved from the results toolbar to the *View Raw SPARQL Response* command, and the toolbar slot it occupied now exports JSON
- Fixed the CSV export escaping single quotes while quoting fields with double quotes, which produced invalid CSV for any value containing a double quote
- Fixed the Markdown export leaving backslashes unescaped, which ended a table cell early
- Fixed the results table offering its graph actions only on the first `GRAPH` variable of a query
- Updated mentor-rdf to 2.1.5, mentor-rdf-parsers to 2.1.0 and mentor-rdf-serializers to 1.9.1

### Version 0.4.2: Multiplatform support and bug fixes
<span class="codicon codicon-calendar"></span> *13th March 2026*
This pre-release version adds support for running Mentor on multiple platforms, meaning Node.js 
targets in VSCode on the Desktop and Web targets in VSCode for the Web. This means that there 
are no-more CORS restrictions when qurying SPARQL endpoints from the desktop. However, CORS 
restrictions still apply when running Mentor in the web, but this can be circumvented by using 
a CORS proxy if needed.

This release also introcduces features to control the inference behavior of SPARQL queries. By default,
the Mentor internal inference graphs are not included in the query execution for workspace queries anymore.
This can be changed by setting the `mentor.inference.enabled` setting to `true`. You can then
choose to enable or disable inference for each query execution in the Code Lens of the sparql query.

### Version 0.2.6
Fixed two minor issues:

1. Auto declaration of prefixes is disabled when manually declaring prefixes in the file header. The auto-implement kicked-in as soon as the ':' was typed and began to resort the prefix definitions without moving the cursor. The new default behavior now is to not run the auto-implement command when manually declaring prefixes.

2. PNAME_NS tokens are now considered for reference counting if they are not part of a prefix declaration. In previous versions of Mentor these tokens were not counted as usages of the namespace and thus lead to invalid markings of namespaces as unused when the namespace prefix was used without a local part.

### Version 0.2.2
This release adds editor functions to automatically define / implement missing prefix definitions in the document. The namespace IRIs for a prefix are looked up in other documents in the workspace first and if not found, are retreived from a local copy of [prefix.cc](https://prefix.cc). The editor also now highights unused prefix definitions and marks them as inactive similar to the behavior of unused imports in other programming languages. Duplicate prefix defintions are marked as a warning. Also some new refactoring methods for prefixes were added:

- Sort prefix definitions in the document header
- Remove unused prefix definitions
- Turn IRI references into prefixed names

There are new settings to adjust the prefix implementation behavior. Prefixes can be implemented by maintaing a sorted list of prefixes at the top of the document (default), or by appending the new prixes after the last prefix defintion. The auto-implementation of prefixes can also be turned off entirely.

Finally this release includes a fix, that addresses a bug caused by the Millan parser that sometimes includes trailing whitespaces in tokens where it should not. Now the find reference command has a more reliable highlighting of the prefix name or IRI.
